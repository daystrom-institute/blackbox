# Knowledge source contract invariants

- This crate is the dependency-clean wire, validation, and canonical-hashing leaf for committed knowledge publication candidates. It never opens a filesystem, invokes Git, serves HTTP, writes a store, accepts publication, computes a corpus view, or links daemon/runtime crates.
- Publication candidates contain committed source facts only. A producer can submit a candidate but cannot move the accepted pointer. No uncommitted workspace state crosses this contract.
- Knowledge and gap manifests use exact repository-relative paths below the published scope's `.bbox/knowledge/` and `.bbox/gaps/` directories. Filenames, counts, bytes, ordering, digests, and limits fail closed.
- Canonical ids use explicit versioned length-prefix encodings. Never replace them with JSON serialization hashes.
- The evidence lane carries exactly one file, `.bbox/evidence/bindings.json`, because one complete valid document replaces one project's accepted binding set. Both the filename and the count fail closed, so the replacement rule is a transport guarantee rather than a reader convention.
- Adding a lane moves two commitments: the lane's own manifest digest (domain-separated by `SourceLaneV1::tag`, which is permanent) and the publication generation identity.
- `LaneVintage` is APPEND-ONLY. Each rung is the exact preimage some shipped binary used, so a new lane adds a rung on top and never edits one below; editing a lower rung orphans every resource that binary wrote. An older rung is admissible only for the exact absent-lane shape a binary of that vintage could have produced, keyed on `SourceManifestDescriptorV1::is_absent_lane`, and a resource carrying content on any newer lane is held to the current rung alone.
- Golden identity literals belong on the rung that minted them. When a lane lands, move the existing generation-id goldens onto the new pre-`<lane>` function rather than restating them for the current vintage; lane-local manifest digests do not move and stay hard goldens.
- Response bodies a client decodes stay tolerant of unknown fields and keep every field a released collector requires, including the ancestry page bounds on `BeginSourceUploadResponseV1`. Request bodies the daemon receives stay `deny_unknown_fields`.
