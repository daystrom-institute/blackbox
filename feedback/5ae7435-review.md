Add a structured `brofile`/`resolved_brofile` field that includes the inline body as-is or the resolved referenced brofile body plus its ref/name.

If a brofile disallows a pattern and the manifest overlay allows the same pattern, `merged_filters.allow` still contains it. AS-T2/design §4.5 says effective post-merge filters are deny-wins; strip exact conflicts from allow and dedupe results. Add a conflict test.

If project-scoped brofiles matter for describe, add `project_dir` to params and test project override behavior; otherwise document that AS-T2 is global-only and keep the warning precise.

6. Existing `bro_agent_describe_filter_merge_deny_wins` does not exercise deny-wins; it only checks overlay allow and disallow appear independently. Make it a real conflict where base disallow beats overlay allow.
